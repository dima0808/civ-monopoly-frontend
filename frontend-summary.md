# Опис фронтенд-частини веб-додатку "Civ Monopoly"

## 1. Загальний огляд

Фронтенд-частина проєкту "Civ Monopoly" являє собою односторінковий веб-додаток (SPA), що реалізує клієнтську частину багатокористувацької настільної онлайн-гри, яка поєднує механіки класичної "Монополії" з тематикою серії стратегічних ігор Civilization. Додаток забезпечує інтерактивний ігровий інтерфейс у реальному часі, систему кімнат (лобі) для збору гравців, чат-комунікацію та управління обліковими записами користувачів.

### 3.2. Патерн архітектури

Додаток побудований на основі **компонентної архітектури React** із застосуванням наступних архітектурних рішень:

- **Односпрямований потік даних (Unidirectional Data Flow)**: стан зберігається у централізованому Redux-сховищі та передається в компоненти через хуки `useSelector`. Дії користувача диспатчуються через `useDispatch` та `createAsyncThunk`.
- **Гібридний підхід до управління даними**: глобальний стан (автентифікація, кімната, конфігурація) зберігається в Redux, тоді як локальний стан (повідомлення чату, поля форм) керується через `useState` всередині компонентів.
- **Поділ відповідальності**: HTTP-запити винесені в окремий шар (`http/requests/`), утиліти — у `utils/`, константи — у `constants/`, що забезпечує чітке розмежування бізнес-логіки та представлення.
- **Portal-паттерн для модальних вікон**: усі діалогові вікна рендеряться через `createPortal` у виділений DOM-елемент `#modal`, що забезпечує правильне відображення поверх основного контенту.

## 4. Система маршрутизації

Маршрутизація реалізована за допомогою бібліотеки `react-router-dom` v7 із підтримкою мовного префіксу в URL-адресах.

| Шлях                       | Компонент           | Опис                                       |
| -------------------------- | ------------------- | ------------------------------------------ |
| `/`                        | `Navigate`          | Перенаправлення на `/home`                 |
| `/:lang`                   | `LanguageValidator` | Валідація мовного префіксу (en/ua)         |
| `/:lang/home`              | `HomePage`          | Головна сторінка з лобі та публічним чатом |
| `/:lang/rules`             | `RulesPage`         | Сторінка з правилами гри                   |
| `/:lang/signin`            | `SignInPage`        | Сторінка авторизації                       |
| `/:lang/signup`            | `SignUpPage`        | Сторінка реєстрації                        |
| `/:lang/game/:reference`   | `Game`              | Ігрова сторінка                            |
| `/:lang/profile/:username` | `Profile`           | Профіль користувача                        |
| `/:lang/*`                 | `ErrorPage`         | Сторінка помилки 404                       |

Компонент `LanguageValidator` синхронізує мовний префікс URL-адреси з поточною мовою бібліотеки i18next та автоматично перенаправляє користувача при невідповідності.

## 5. Управління станом (Redux Toolkit)

Централізоване сховище стану побудоване на Redux Toolkit та складається з 7 зрізів (slices):

### 5.1. authSlice — Автентифікація

Зберігає об'єкт поточного автентифікованого користувача. Реалізує асинхронний thunk `getMe`, який виконує запит `GET /users/current` для отримання профілю за JWT-токеном. Редуктор `logout` очищує токен з cookies та скидає стан користувача.

### 5.2. roomSlice — Стан кімнати

Зберігає поточну ігрову кімнату з масивом учасників, їхніми позиціями, обраними цивілізаціями та кольорами. Оновлюється як через REST API (початкове завантаження), так і через WebSocket (оновлення в реальному часі). Має редуктори `setRoom` та `updateMember`.

### 5.3. configSlice — Конфігурація гри

Кешує конфігурацію ігрового поля (типи комірок, ціни, рівні покращень) та загальну конфігурацію гри (ери, варіанти витрат на армію). Завантажується асинхронними thunks `getPropertiesConfig` та `getGameConfig`.

### 5.4. wsSlice — WebSocket-з'єднання

Зберігає статус підключення WebSocket. STOMP-клієнт зберігається як змінна на рівні модуля (а не в Redux-стані), що дозволяє уникнути проблем із серіалізацією несеріалізованих об'єктів.

### 5.5. notificationSlice — Система сповіщень

Керує чергою toast-сповіщень з автоматичним зникненням. Кастомний thunk `pushNotification` послідовно диспатчує: додавання сповіщення, позначення як зникаючого (через 5 с), видалення (через 6 с) — за допомогою `setTimeout`.

### 5.6. chatSlice — Приватний чат

Керує станом видимості діалогу приватного чату та посиланням на поточно відкритий чат.

### 5.7. gameSlice — UI-стан гри

Зберігає обрану вкладку панелі дій (EVENTS / MANAGEMENT) та індекс обраних витрат на армію (`armySpendingIndex`, за замовчуванням 1). Редуктори: `setSelectedTab`, `setArmySpendingIndex`.

## 6. Взаємодія з сервером

### 6.1. REST API (HTTP)

Взаємодія з бекендом здійснюється через HTTP-клієнт Axios. Базова URL-адреса формується з конфігураційних змінних середовища: `{HTTP_PROTOCOL}://{IP}{BACKEND_PORT}/api/v1`.

**Інтерсептори Axios:**

- **Request-інтерсептор**: автоматично додає заголовок `Authorization: Bearer {token}` до кожного запиту, отримуючи JWT-токен з cookies.
- **Response-інтерсептор**: витягує деталі помилки з `error.response.data.detail` для уніфікованої обробки помилок.

**Групи ендпоінтів:**

| Група              | Базовий шлях     | Ендпоінти                                                                                                                                 |
| ------------------ | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Автентифікація** | `/auth`          | `POST /register`, `POST /login`                                                                                                           |
| **Користувачі**    | `/users`         | `GET /current`, `GET /{username}`, `PUT /avatar`                                                                                          |
| **Кімнати**        | `/rooms`         | `GET /`, `GET /{reference}`, `POST /`, `POST /join/{reference}`, `POST /kick/{memberReference}`, `POST /leave`                            |
| **Ігрові дії**     | `/games`         | `GET /civilizations`, `GET /colors`, `POST /start`, `POST /roll-dice`, `POST /end-turn?armySpendingIndex=N`                               |
| **Учасники**       | `/members`       | `POST /change-civilization`, `POST /change-color`                                                                                         |
| **Властивості**    | `/properties`    | `POST /buy`, `POST /pay-rent`, `GET /room/{ref}`, `POST /upgrade`, `POST /mortgage`, `POST /demote`, `POST /buyback`, `GET /requirements` |
| **Події**          | `/events`        | `GET /`, `POST /skip/{type}`                                                                                                              |
| **Публічний чат**  | `/chats/public`  | `GET /{reference}`, `POST /{reference}`, `DELETE /{chatRef}/{msgRef}`, `PUT /mute/{username}`, `PUT /unmute/{username}`                   |
| **Приватний чат**  | `/chats/private` | `GET /`, `POST /`, `GET /{reference}`, `GET /between`, `POST /{reference}`                                                                |
| **Конфігурація**   | `/configs`       | `GET /properties`, `GET /game`                                                                                                            |

### 6.2. WebSocket (STOMP)

Для забезпечення комунікації в реальному часі використовується протокол STOMP поверх WebSocket. З'єднання встановлюється при монтуванні кореневого компонента `App.jsx` з автоматичним перепідключенням кожні 5 секунд.

**Підписки на теми (Topics):**

| Тема                              | Компонент-підписник | Типи подій                                                                                                                                                            |
| --------------------------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/topic/rooms`                    | `LobbyList`         | CREATE, JOIN, LEAVE, KICK, DELETE                                                                                                                                     |
| `/topic/rooms/{reference}`        | `MemberList`        | JOIN, LEAVE, KICK, DELETE, CHANGE_CIVILIZATION, CHANGE_COLOR                                                                                                          |
| `/topic/games/{reference}`        | `Game`              | START, END_TURN, FORCE_END_TURN, ROLL_DICE, FORCE_ROLL_DICE, NEW_TURN, PROPERTY_BUY, PROPERTY_UPGRADE, PROPERTY_MORTGAGE, PROPERTY_DEMOTE, PROPERTY_BUYBACK, RENT_PAY |
| `/topic/chats/{reference}`        | Компоненти чату     | SEND, DELETE                                                                                                                                                          |
| `/user/{username}/events`         | `Game`              | ADD_EVENT, DELETE_EVENT, DELETE_ALL_EVENTS                                                                                                                            |
| `/user/{username}/notifications`  | `App`               | PRIVATE_MESSAGE_SENT, USER_WAS_KICKED, USER_BECAME_OWNER                                                                                                              |
| `/user/{username}/chats/contacts` | `ContactList`       | SEND, DELETE                                                                                                                                                          |

Персональні підписки (`/user/...`) включають JWT-токен у заголовках для автентифікації.

## 7. Компоненти інтерфейсу

### 7.1. Шапка (Header)

- **Header** — основна шапка додатку з адаптивним бургер-меню для мобільних пристроїв. Компонує `LeftHeader` (логотип, посилання на правила) та `RightHeader` (перемикач мови з прапорцями, кнопки входу/виходу, посилання на профіль, кнопка приватного чату).
- **SimpleHeader** — мінімальна шапка для сторінок авторизації, що відображає лише логотип.

### 7.2. Система лобі (Lobby)

- **LobbyList** — відображає список усіх створених кімнат. Початково завантажує дані через REST API, після чого підписується на WebSocket-тему `/topic/rooms` для оновлення у реальному часі. Містить кнопку створення нової кімнати.
- **Lobby** — картка окремої кімнати, що показує назву, учасників з аватарами, кнопки приєднання/виходу та індикатор початку гри з посиланням на ігрову сторінку. Підтримує кімнати із захистом паролем.
- **CreateLobbyDialog** — модальне вікно для створення кімнати з полями: назва, кількість гравців (2–6, вибір через радіо-кнопки), опціональний пароль з перемикачем видимості. Рендериться через `createPortal`.
- **JoinLobbyDialog** — модальне вікно для введення паролю кімнати перед приєднанням.
- **Member** — компонент відображення учасника лобі з аватаром, ім'ям та кнопкою вигнання (для власника кімнати).

### 7.3. Чат-система

#### Публічний чат

- **Chat (public)** — чат головної сторінки. Завантажує повідомлення за референсом, підписується на WebSocket для подій SEND/DELETE. Призначає циклічні кольори відправникам. Обмеження на довжину повідомлення — 250 символів.
- **Message (public)** — окреме повідомлення з іменем відправника-посиланням на профіль.

#### Приватний чат

- **PrivateChatDialog** — модальне вікно, що компонує список контактів та область чату.
- **ContactList** — список контактів з дебаунс-пошуком та оновленнями в реальному часі через WebSocket.
- **Contact** — картка контакту з аватаром, іменем та превью останнього повідомлення.
- **Chat (private)** — область приватного листування з підтримкою створення нового чату при першому повідомленні.
- **Message (private)** — повідомлення з розрізненням "своє/чуже", групуванням повідомлень у стилі Telegram (заокруглені кути, "хвостик" для першого та останнього повідомлення в групі).

### 7.4. Ігрова дошка

- **Board** — центральний компонент ігрового поля. Реалізований як CSS Grid 3×3 (кутові клітинки + бокові панелі). Рендерить 4 кутові клітинки (Старт, Проєкти ×2, Бермудський трикутник), 4 бокові панелі по 12 комірок кожна, чат у центрі та анімовані ігрові фішки.
- **SideBoard** — рядок/стовпець з 12 комірок для однієї сторони дошки. Визначає орієнтацію (горизонтальна/вертикальна) та дзеркальне відображення залежно від розташування.
- **Cell** — комірка властивості. Показує ціну (або gold on step / tourism on step для куплених), зображення найвищого рівня покращення з таблиці CELL_IMAGES, кольоровий фон власника (градієнт `color-{color}-g`), зірки покращень (сині для кожного рівня після першого, одна жовта при повному покращенні) та індикатор застави (іконка замка з кількістю ходів та сірий фон з `grayscale` фільтром).
- **EdgeCell** — кутова клітинка з направленими заокругленнями рамки.
- **BarbCell** — спеціальна клітинка "Варвари" з червоною кольоровою схемою.
- **GoodyHutCell** — спеціальна клітинка "Goody Hut" із зеленою кольоровою схемою.

#### Ігровий чат (центр дошки)

- **Chat (game)** — чат всередині ігрового поля. Використовує референс кімнати для публічної теми чату. Повідомлення відображаються з кольором, що відповідає кольору гравця.
- **Message (game)** — повідомлення з кольором відправника та міткою часу.

### 7.5. Система учасників гри

- **MemberList** — ліва панель зі списком усіх гравців. Підписується на WebSocket для оновлень кімнати та ігрових подій. Відображає кнопки виходу/додому/старту, індикатор ери та лічильник ходів.
- **Member (game)** — картка гравця з портретом лідера цивілізації, іменем, назвою цивілізації та кнопкою вигнання.
- **MemberSetupDialog** — повноекранне модальне вікно для передігрового налаштування: вибір лідера, вибір кольору, інформація про лідера.
- **MemberChooseLeader** — прокручуваний список усіх цивілізацій з API. Відображає вже обрані (неактивні) та поточно обрані.
- **LeaderOption** — картка цивілізації (зображення + ім'я + назва цивілізації). Виклик API `changeCivilization()` при натисканні.
- **MemberChooseColor** — сітка кольорових зразків з API. Показує обраний/зайнятий стан. Виклик API `changeColor()` при натисканні.
- **Era** — відображає поточну еру (від Стародавньої до Інформаційної) на основі номера ходу та конфігурації гри. Значення конфігурації ер інтерпретуються як початковий хід кожної ери (ANCIENT: 0–9, CLASSICAL: 10–24, ...). Остання ера відображається з символом "+" (наприклад, "Information era: 100+").

### 7.6. Панель дій

- **Actions** — права панель з навігацією по вкладках (EVENTS / MANAGEMENT). Обчислює `hasAvailableUpgrade` для зеленого індикатора на кнопці Empire (перевіряє наявність хоча б однієї власної нерозсаленої нерухомості з виконаними вимогами та достатнім золотом). Передає `ownedProperties` та `propertyRequirements` дочірнім компонентам.
- **TopPanel** — відображає загальне золото за хід (обчислюється як сума gpt усіх покращень усіх власних нерухомостей), варіанти витрат на армію з логікою вибору/блокування, кнопку налаштувань та кнопки управління Імперією/Перемогами. Зелена кулька (клас `available-upgrade`) на кнопці Empire показується, коли є доступне покращення. Автоматично скидає вибір армійських витрат на індекс 0, якщо обраний варіант стає недоступним.
- **ArmySpending** — окремий варіант витрат на армію із зазначенням приросту сили та вартості у золоті. Підтримує стани: обраний (помаранчева рамка `selected-military`), заблокований (сірий фільтр `li-army-gold-disabled`), звичайний. Вибір зберігається в Redux (`armySpendingIndex`).
- **Events** — журнал подій та кнопки "Кинути кубики" / "Завершити хід". Кнопки відображаються лише коли настає хід поточного користувача. При завершенні ходу передає `armySpendingIndex` до API `endTurn(armySpendingIndex)`.
- **BuyProperty** — картка події купівлі нерухомості. Відображає назву, зображення, статистику (ціна, gold on step, gold per turn, tourism). Показує вимоги для покупки у вигляді блоків-пілюль: виконані — світлий фон (#cfd1d3cd), невиконані — темний фон (#9a9c9ecd) з червоним текстом (#641a2b). Кнопка "buy" заблокована, якщо не вистачає золота або не всі вимоги виконані.
- **ForeignProperty** — картка події оплати ренти. Відображає фон кольору власника (градієнт `color-{color}-g`), зображення найвищого рівня покращення, gold on step з множником кидка.

#### Управління імперією (Empire)

- **Empire** — компонент управління власними нерухомостями. Відображає прокручуваний список карток нерухомостей поточного гравця. Кожна картка включає:
  - Фон градієнтом кольору гравця (`color-{color}-g`)
  - Назву нерухомості
  - Зображення найвищого рівня покращення
  - Сумарну статистику (gold on step, gold per turn, tourism) усіх куплених рівнів
  - Картки рівнів покращень з трьома візуальними станами:
    - **Куплений** (`empire-level-owned`): зелена рамка + білий фон
    - **Наступний рівень** з виконаними вимогами (`empire-level-next`): білий фон без рамки
    - **Наступний рівень** з невиконаними вимогами: звичайний сірий фон, невиконані вимоги червоним текстом
    - **Майбутні рівні** (`empire-level-future`): grayscale 60% + opacity 0.6
  - Кожна картка рівня містить: зображення будівлі (UPGRADE_IMAGES для рівнів вище LEVEL_1, CELL_IMAGES для LEVEL_1), список вимог (REQUIREMENT_DESCRIPTIONS), статистику (cost, g.o.s, t.o.s, g.p.t)
  - Кнопки дій: upgrade (заблоковано якщо не хід гравця, не виконані вимоги або не вистачає золота), redeem (для заставлених), demote/pledge
  - Індикатор застави: сірий фон з іконкою замка та кількістю ходів (CSS `::after` з `var(--mortgage-value)`)
  - Вимоги (`propertyRequirements`) завантажуються з `GET /properties/requirements` та оновлюються після: кидка кубиків, завершення ходу, купівлі, покращення, застави, зниження, викупу

### 7.7. Система сповіщень

- **NotificationList** — стек toast-сповіщень у правому верхньому куті, що рендериться через `createPortal`. Підтримує три типи: MESSAGE, ERROR, OTHER. Містить кнопку "Очистити всі".
- **MessageNotification** — сповіщення про приватне повідомлення. Натискання відкриває чат з відправником.
- **ErrorNotification** — червоне сповіщення про помилку.
- **OtherNotification** — оранжеве/жовте сповіщення для загальних подій (вигнання, отримання статусу власника).

### 7.8. Компоненти профілю

- **ProfileImage** — відображення аватара з можливістю зміни (прихований `<input type="file">`). Завантаження через API `changeAvatar()`. Редагується лише на власному профілі.
- **ProfileStats** — ім'я користувача, іконка рангу, рейтинг ELO, статистика ігор (зіграно, виграно, середнє місце). Кнопка "Написати повідомлення" для перегляду чужого профілю.
- **ProfileCredentials** — зміна паролю (поля для поточного та нового паролю). Відображається лише на власному профілі.
- **Achievements** — панель досягнень користувача.

## 8. Анімація ігрових фішок

Одним з ключових елементів фронтенду є система покрокової анімації руху ігрових фішок по дошці. Реалізація включає:

1. **Обчислення позицій**: функція `calculatePosition()` в `utils/game.js` перетворює індекс комірки (0–47) у піксельні координати (top/left) на дошці розміром 820×720 пікселів.

2. **Побудова шляху**: функція `getPath()` обчислює послідовність проміжних кутових позицій для анімації через них, забезпечуючи природний рух фішки вздовж периметру дошки.

3. **Покрокова анімація**: компонент `Board.jsx` відстежує попередні позиції через `useRef`. При зміні позицій учасників (через WebSocket) обчислюється шлях, і кожен крок анімується через `setTimeout` з інтервалом 1000 мс.

4. **Накладання фішок**: функція `getTransform()` забезпечує зміщення для до 6 фішок, що знаходяться на одній комірці, запобігаючи їх перекриванню.

5. **CSS-переходи**: плавність руху забезпечується CSS-властивістю `transition: all 0.6s ease-in-out`.

## 10. Автентифікація та авторизація

### 10.1. Механізм автентифікації

Система автентифікації базується на JWT-токенах (JSON Web Tokens):

1. **Реєстрація/Вхід**: користувач надсилає облікові дані через форму → API повертає JWT-токен → токен зберігається у cookies браузера через бібліотеку `js-cookie`.
2. **Автоматична автентифікація**: при завантаженні додатку (`App.jsx`) виконується запит `GET /users/current` з JWT-токеном з cookies для відновлення сесії.
3. **Вихід**: очищення токена з cookies, скидання стану користувача в Redux, перенаправлення на головну сторінку.

### 10.2. Захист маршрутів

Явних захищених маршрутів (route guards) у додатку немає. Замість цього окремі компоненти перевіряють наявність об'єкта `user` в Redux-стані та вимикають функціональність (введення повідомлень у чаті, кнопка створення кімнати тощо) для неавтентифікованих користувачів.

### 10.3. WebSocket-автентифікація

Персональні WebSocket-підписки (`/user/{username}/...`) включають JWT-токен у заголовках запиту для забезпечення автентифікації.

## 11. Інтернаціоналізація (i18n)

Додаток підтримує дві мови — **українську** та **англійську** — за допомогою бібліотеки i18next з наступними модулями:

- **react-i18next** — інтеграція з React через хук `useTranslation()`.
- **i18next-browser-languagedetector** — автоматичне визначення мови браузера.

Мовний префікс вбудований у URL-маршрут (`/en/home`, `/ua/rules`), що забезпечує можливість прямого посилання на контент певною мовою. Компонент `LanguageValidator` синхронізує мову URL з поточною мовою i18next. Перемикання мови здійснюється через інтерфейс шапки (іконки прапорців).

## 13. Ігровий процес (User Flow)

### Фаза 1: Головна сторінка / Лобі

1. Користувач потрапляє на `HomePage`, де бачить список кімнат (LobbyList) з оновленнями у реальному часі та публічний чат.
2. Може **створити кімнату** (назва, 2–6 гравців, опціональний пароль) через `CreateLobbyDialog`.
3. Може **приєднатися до кімнати**, натиснувши кнопку "+" на вільному слоті (діалог паролю при необхідності).

### Фаза 2: Кімната / Передігрове налаштування

1. Після приєднання користувач переходить на ігрову сторінку `/game/{reference}`.
2. Завантажується конфігурація кімнати, ігрового поля та гри.
3. Кожен гравець може **обрати цивілізацію** та **колір** через `MemberSetupDialog`.
4. Зміни цивілізації та кольору транслюються у реальному часі через WebSocket.
5. Лідер кімнати (перший учасник) бачить кнопку "Старт".

### Фаза 3: Початок гри

1. Лідер натискає "Старт" → REST API → сервер транслює подію START.
2. Інтерфейс трансформується: з'являються індикатор ери, лічильник ходів, кнопки ігрових дій.
3. Фішки гравців відображаються на стартовій позиції.
4. Завантажуються всі нерухомості кімнати (`GET /properties/room/{ref}`), події гравця (`GET /events`) та вимоги (`GET /properties/requirements`).

### Фаза 4: Ігровий цикл

1. Активний гравець (визначається `room.turnIndex`) бачить кнопку "Кинути кубики".
2. Натискання → API `rollDice()` → сервер транслює ROLL_DICE з оновленими позиціями.
3. Дошка анімує покрокове переміщення фішки через проміжні позиції.
4. Після кидка можуть з'явитися події (BUY_PROPERTY, FOREIGN_PROPERTY) через WebSocket підписку `/user/{username}/events`.
5. Гравець обробляє події (купує/пропускає нерухомість, платить ренту).
6. Після обробки подій з'являється кнопка "Завершити хід".
7. Натискання → API `endTurn(armySpendingIndex)` → сервер транслює END_TURN зі зміненим індексом ходу.
8. Сервер може примусово виконувати дії: `FORCE_ROLL_DICE`, `FORCE_END_TURN` (таймаути).
9. Ера змінюється відповідно до номера ходу.
10. При повідомленні `NEW_TURN` зменшується лічильник застави на кожній заставленій нерухомості; нерухомості з лічильником 0 видаляються.

### Фаза 5: Під час гри

- Ігровий чат (центр дошки) забезпечує комунікацію всіх гравців у реальному часі.
- Гравець обирає варіант витрат на армію (сила/золото) перед завершенням ходу; недоступні варіанти заблоковані.
- Вкладка Management/Empire дозволяє переглядати та керувати власними нерухомостями: покращувати, знижувати рівень, заставляти та викупляти.
- На дошці відображаються: кольори власників, зірки покращень (сині/жовта), іконки застави з лічильником ходів.
- Вимоги для покращень завантажуються динамічно та оновлюються при кожній значущій ігровій дії.
- Зелений індикатор на кнопці Empire сигналізує про наявність доступних покращень.

| `VITE_WS_PROTOCOL`          | Протокол WebSocket-з'єднання (ws/wss) |

### 15.2. ESLint

Конфігурація ESLint у форматі flat config з підтримкою плагінів `react-hooks` та `react-refresh`. Правило `no-unused-vars` налаштоване ігнорувати змінні, що починаються з великої літери або підкреслення.

### 15.3. Prettier

Конфігурація форматування: крапка з комою, одинарні лапки, завершальні коми, ширина рядка 80 символів, відступ у 2 пробіли, символ нового рядка LF.

## 16. Висновки

Фронтенд-частина "Civ Monopoly" являє собою повноцінний клієнтський додаток для багатокористувацької онлайн-гри з наступними ключовими характеристиками:

- **Реактивний інтерфейс**: побудований на React 19 з використанням сучасних хуків (`useState`, `useEffect`, `useRef`, `useSelector`, `useDispatch`, `useNavigate`, `useParams`, `useTranslation`).
- **Комунікація в реальному часі**: повноцінна інтеграція WebSocket через STOMP-протокол для миттєвого оновлення стану гри, чатів та лобі.
- **Централізоване управління станом**: Redux Toolkit забезпечує передбачуваний потік даних та легке відлагодження.
- **Багатомовність**: повна підтримка української та англійської мов з мовним префіксом у URL.
- **Адаптивний дизайн**: коректне відображення на пристроях різних розмірів завдяки медіа-запитам.
- **Модульна архітектура**: чіткий поділ на шари (представлення, стан, мережева взаємодія, утиліти) забезпечує підтримуваність та розширюваність коду.
- **Анімації**: покрокова анімація руху ігрових фішок з обчисленням проміжних позицій та CSS-переходами.
